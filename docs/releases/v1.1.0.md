## English

Ozyune v1.1.0 turns waiting into being told. While a dsh agent works, Ozyune posts a macOS
system notification when the agent needs your judgment, and when a run ends in a way you did not
ask for. Clicking a notification brings the window back.

### New

- **Needs your judgment** — permission approvals, `ask_user_question` prompts, and
  `exit_plan_mode` plan reviews.
- **Run outcomes** — task complete, run failed, and stopped early (a rejected step, or an
  output-token ceiling).
- **Quiet when you caused it** — pressing stop yourself, or a hook, parent agent or teardown
  cancelling the run, posts nothing.
- **Click to focus** — clicking a notification activates Ozyune and brings its window to the front.
- **Notification settings pane** — three delivery modes (default: only when Ozyune isn't
  frontmost / Always / Never), live permission status, and a Send Test Notification button
  that verifies the whole path.

### Fixed

- **`target=_blank` / `window.open` silently doing nothing** — a newer SDK changed the Swift
  name imported for `WKUIDelegate`'s `createWebViewWith`. The old spelling still compiled but no
  longer witnessed the optional requirement, so WebKit never called it.

### How it works

- **Read-only side channel** — an injected page script subclasses `WebSocket` to observe the
  live frames between the dsh Web UI and its host. It never sends requests to the host and
  leaves your dsh configuration untouched.
- **Structural classification** — only live journal `event` items are considered, so history
  replays, assistant streaming chunks, and message content that merely quotes an event name
  cannot produce a false notification.
- **Page-side prefilter** — assistant chunks are dropped in the page and never cross the
  JavaScript-to-native bridge.
- **Delivery policy** — a 10-second per-kind cooldown, consumed only when a banner is actually
  posted; a denied permission degrades silently and never disturbs the main flow.

### Engineering

- Added `scripts/check-signal-classifier.sh` — 20 fixtures built from real frames — and wired it
  into CI and the pre-release check, so a dsh wire-vocabulary change fails the build instead of
  silently disabling notifications.
- `scripts/preflight.sh` grew to 8 checks, with the source-only fixture check first because it
  needs no app bundle.

### Known limitations

- Notifications depend on dsh's Web wire vocabulary (verified against dsh `0.1.5-rc.3`).
  A renaming release makes them go quiet — use `OZYUNE_DEBUG_SIGNALS=1` to trace, and the
  fixtures will flag it in CI first.
- Only the main frame's WebSocket is observed; connections opened inside iframes are out of scope.
- Notifications exist only while Ozyune is running (the signals come from the embedded
  WebView's live traffic), and their copy is generic — no session titles.

### Requirements

- macOS 14 or later.
- dsh installed separately — Ozyune is only a shell and does **not** bundle the runtime:
  ```bash
  npm install --global @deepseek-ai/dsh
  ```
- The first launch asks for notification permission; if nothing ever appears, allow Ozyune in
  System Settings → Notifications.
- Building from source requires code signing (`DEVELOPMENT_TEAM` in `Local.xcconfig`): macOS's
  notification service rejects ad-hoc and unsigned builds, and those builds never see the
  permission prompt.

### Installation

1. Download `Ozyune.zip` from the assets below
2. Unzip and move `Ozyune.app` to `/Applications`
3. Launch Ozyune — it boots dsh and loads the Web UI automatically

## 简体中文

Ozyune v1.1.0 把「等待」变成「被通知」：dsh agent 干活期间，只要它需要你判断、或一次运行以你没要求的方式结束，
Ozyune 就发一条 macOS 系统通知；点击通知即可把窗口唤回。

### 新增

- **需要你的判断** —— 权限批准提示、`ask_user_question` 提问、`exit_plan_mode` 计划评审。
- **运行结果** —— 任务完成、运行失败、未跑完就结束（步骤被拒，或触到输出 token 上限）。
- **你自己造成的不打扰** —— 自己按下停止，或 hook、父 agent、退出触发的取消，一律不推送。
- **点击聚焦** —— 点通知即激活 Ozyune 并把窗口置前。
- **通知设置面板** —— 三档推送时机（默认「仅当 Ozyune 不在前台」/ 始终 / 关闭）、实时权限状态，
  以及一键验证整条链路的 Send Test Notification。

### 修复

- **`target=_blank` / `window.open` 静默失效** —— 新版 SDK 更改了 `WKUIDelegate` 中
  `createWebViewWith` 的 Swift 导入名。旧写法仍能编译，但不再满足协议要求，WebKit 因此从不调用它。

### 实现方式

- **只读旁路** —— 注入页面的脚本子类化 `WebSocket`，观测 dsh Web UI 与 Host 之间的实时帧；
  不向 Host 发任何请求，也不改动你的 dsh 配置。
- **结构化分类** —— 只认实时 journal `event`，因此历史快照回放、assistant 流式分片、正文里引用事件名
  都不会造成误报。
- **页面侧预过滤** —— assistant 分片在页面即被丢弃，不跨 JS→native 桥。
- **投递策略** —— 同类通知 10 秒冷却，且冷却只在真正投递时消耗；权限被拒静默降级，绝不影响主流程。

### 工程质量

- 新增 `scripts/check-signal-classifier.sh` —— 基于真实帧的 20 项 fixture —— 并接入 CI 与发版前检查：
  dsh 若改动 wire 词汇表，会直接构建失败，而不是让通知静默失效。
- `scripts/preflight.sh` 扩为 8 项检查，fixture 检查排在首位，因为它不依赖 app bundle。

### 已知限制

- 通知依赖 dsh 的 Web wire 词汇表（本次基于 dsh `0.1.5-rc.3` 逐项核对）。dsh 若在大版本中改名，
  通知会静默失效——用 `OZYUNE_DEBUG_SIGNALS=1` 排查，而 fixture 会先在 CI 报警。
- 仅观测主框架的 WebSocket，iframe 内建立的连接不在观测范围。
- 通知只在 Ozyune 运行期间产生（信号来自内嵌 WebView 的实时流量），且文案为通用文案，不含会话标题。

### 系统要求

- macOS 14 或更高版本。
- 需自行安装 dsh —— Ozyune 只是一个外壳，本身**不内置**运行时：
  ```bash
  npm install --global @deepseek-ai/dsh
  ```
- 首次启动会请求通知权限；若始终收不到，请在 系统设置 → 通知 中允许 Ozyune。
- 从源码自行构建需要签名（`Local.xcconfig` 中的 `DEVELOPMENT_TEAM`）：macOS 通知服务不接受
  ad-hoc / 无签名构建，这类构建下授权弹窗不会出现。

### 安装

1. 下载下方 Assets 中的 `Ozyune.zip`
2. 解压后将 `Ozyune.app` 移入「应用程序」
3. 启动 Ozyune —— 它会自动拉起 dsh 并加载 Web 界面
